# AI-Built Mobile Games for AdMob Revenue — Not Viable

## What It Claims to Be

An r/passive_income post (score 320, ID: 1sdwj6k) described a solo developer building 3 App Store games using Cursor + Claude Code over 4 months — all generating passive AdMob income. The pattern: AI writes the game code end-to-end → submit to App Store/Google Play → AdMob runs ads inside → passive income indefinitely. With AI removing the development bottleneck, the theoretical flywheel is: build 1 game/week → 50+ games → significant passive AdMob income.

## Why It Doesn't Work Agentically

- **App Store and Google Play submissions require human accounts and manual steps.** Apple's App Store Connect requires an Apple Developer account ($99/year), Xcode setup, and manual review submission — there is no batch API for initial app submissions. Google Play has a developer API but only for *managing existing apps*, not submitting new ones. Every new game requires a human-initiated upload and review trigger.
- **Apple review takes 1-3 days with human review required.** Apple runs manual review on all new submissions. There's no automated pathway. A fully autonomous pipeline stalls at this step.
- **Discovery is the real bottleneck.** App Store submissions grew 30% YoY to ~600,000 in the most recent period. Without ASO investment and some marketing, AI-built games will receive essentially zero organic downloads. AdMob pays per impression/click — zero downloads = zero revenue. The original poster had 4 months and human involvement in promotion.
- **Apple and Google have tightened AI-generated content scrutiny.** Apps with obvious low-effort AI-generated assets or gameplay are more frequently rejected or removed in post-approval review (2026 guidelines). Bulk submission patterns from a single developer account trigger policy review.
