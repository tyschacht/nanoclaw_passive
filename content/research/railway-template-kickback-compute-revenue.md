# Railway Template Kickback — 25% of Compute Revenue Forever

## What It Is

Railway (railway.app) is a cloud deployment platform that raised $100M Series B and serves 332,000+ paying customers as of Q4 2025. Unlike most app/template marketplaces where you earn a one-time sale or subscription fee, Railway's **Template Kickback Program** pays creators 25% of all compute spending generated by every deployment of their template — ongoing, for as long as the deployment runs.

The math: if 50 users each deploy your template and spend $30/month running it on Railway's compute = $1,500/month in total compute → creator earns **$375/month** from a single template, in perpetuity, with zero ongoing effort. The template marketplace has hit nearly $3M GMV total and paid out ~$1M to creators, growing at 30%+ month-over-month. Some individual template authors have earned $10,000+ in kickbacks.

The agentic pipeline: Claude Code generates Docker-based deployment configurations (one-click templates for popular open-source tools), which are linked to a public GitHub repo. The creator clicks one "Publish" button in Railway's web UI (one-time per template), then the template goes live. All updates push automatically via GitHub merges — fully headless. Income accrues passively as long as users keep their deployments running.

This is structurally distinct from all existing marketplace reports: income is proportional to compute consumption, not subscriptions or one-time payments. Templates for resource-hungry services (AI inference servers, workflow automation, databases with rich UIs) generate far more kickback per user than lightweight apps.

## How an Agent Does It

1. **Market research**: Agent scans Railway template marketplace (railway.com/templates) for gaps — categories with <5 templates, high-demand tools (AI inference servers, agent orchestration, data pipelines) that don't yet have Railway templates.
2. **Build the template**: Claude Code generates:
   - Public GitHub repo with `Dockerfile` or `docker-compose.yml`
   - `railway.json` (service configuration, environment variables, health checks)
   - `README.md` with one-click deploy button and setup instructions
   For complex multi-service templates: separate service directories, Railway's template composer format.
3. **Push to GitHub**: `git push origin main` — fully agentic. Agent can maintain and update templates via git commits.
4. **Submit (one-time human step)**: Open Railway dashboard → Project Settings → Convert to Template → fill web form (~5 minutes). This is the only human action required per template.
5. **Template goes live**: Railway shows it in the marketplace with a one-click deploy button. No further human action needed.
6. **Passive income loop**: As users deploy the template and run workloads, Railway tracks compute usage and sends 25% to creator via GitHub Sponsors or Buy Me a Coffee. Agent monitors GitHub stars/deployments to prioritize which template categories to expand next.
7. **Updates (fully headless)**: When Claude improves the template (security patches, new features, performance tweaks), it commits to the GitHub repo. Railway auto-pushes updates to all active deployments. No re-review required.
8. **Scale**: Agent generates templates for 10-20 additional tools in high-compute categories. Portfolio income stacks.

## Implementation Notes

**Template creation stack:**
- `Dockerfile` or `docker-compose.yml` for service definition
- `railway.json` for Railway-specific config (healthcheck, restart policy, env defaults)
- `README.md` with deploy button: `[![Deploy on Railway](https://railway.com/button.svg)](https://railway.com/template/TEMPLATE_ID)`
- GitHub public repo linked to Railway service

**Highest-kickback template categories (maximize compute consumption):**
1. **AI inference servers**: Ollama (LLM hosting), LiteLLM (proxy), OpenWebUI (Ollama UI), LocalAI — GPU compute = highest $/hour on Railway
2. **Workflow automation**: n8n self-hosted, Zapier alternatives, Temporal — runs 24/7, medium compute
3. **Agent orchestration**: Paperclip self-hosted, OpenClaw self-hosted, Langflow — trending April 2026
4. **Analytics/BI**: Plausible, Umami, Metabase, Grafana with ClickHouse — always-on, high memory
5. **Data pipelines**: Airflow, Prefect, Dask — periodic heavy compute bursts
6. **Databases with UI**: PocketBase, Supabase self-hosted, NocoDB — persistent storage = persistent compute

**Revenue calculation:**
- Railway's base compute: $0.000463/vCPU/minute, $0.000231/RAM GB/minute
- A template using 2 vCPU + 4GB RAM running 24/7 ≈ $35/month per user
- 25% kickback = $8.75/user/month
- 100 active deployments = $875/month from one template

**Payment mechanics:**
- Minimum $100 to withdraw
- Paid via GitHub Sponsors or Buy Me a Coffee (Rails notes Stripe Connect is planned)
- Monthly payout cycle
- Railway tracks deployment-hours automatically — no manual reporting

**Template update pipeline:**
```bash
# Agent updates template and pushes - Railway auto-propagates
git add .
git commit -m "chore: update base image, fix env defaults"
git push origin main
# Railway detects GitHub push → offers update to all template users
```

**Technology Partner Program (optional uplift):**
- If you're maintaining an open-source project, join Railway's Technology Partners program
- Earn commission on ALL Railway templates that use your technology (even templates others built)
- This is enterprise revenue share — relevant if the agent builds novel open-source tools, not just templates for existing tools

## Open Questions

1. **Payout method maturity**: GitHub Sponsors / Buy Me a Coffee are functional but not bank-grade. Railway mentioned planning Stripe Connect — worth re-checking timing.
2. **Compute rate assumptions**: Heavy GPU templates earn far more per user. Railway offers GPU instances (T4, A100) — are GPU-hour kickbacks included in the 25%?
3. **Template review time**: How long from submission to marketplace listing? Is there a human review or automated checks?
4. **Top-template slots**: Does Railway algorithmically promote certain templates (more deployments → more income)? If so, what's the ranking signal?
5. **n8n template gap check**: Does a high-quality n8n template already exist, or is there room for a better one? Check railway.com/templates before building.
